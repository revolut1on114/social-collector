# Звіт: колектор публічних постів Mastodon

## Джерело

**Mastodon** — децентралізована соцмережа з офіційним відкритим REST API. Публічні стрічки читаються без реєстрації, а кожна відповідь чесно віддає заголовки лімітів. Збирали три стрічки на двох інстансах:

| Стрічка | Endpoint | Записів |
|---|---|---|
| `mastodon.social:tag:osint` | `/api/v1/timelines/tag/osint` | 600 |
| `mastodon.social:tag:ukraine` | `/api/v1/timelines/tag/ukraine` | 531 |
| `mstdn.social:account:bellingcat` | `/api/v1/accounts/:id/statuses` | 600 |
| `infosec.exchange:tag:osint` | `/api/v1/timelines/tag/osint` | 0 — див. нижче |

**Після backfill — 1731 унікальний запис** від 134 авторів (з контрольними прогонами — 1739), з них 499 з медіа. Діапазон дат постів: 31.10.2024 – 16.10.2026 (довга історія — з акаунта Bellingcat після backfill).

## Які ліміти зустріли

**1. Квота запитів: 300 запитів на 5 хвилин** (на обох інстансах). Це видно із заголовків, а не з документації:

```
X-RateLimit-Limit: 300
X-RateLimit-Remaining: 298
X-RateLimit-Reset: 2026-10-16T07:20:00.185034Z
```

Що помітили емпірично:
- **Квота рахується на IP, а не на клієнта.** Перший же запит показав `Remaining: 227` з уже минулим `Reset: 07:15`, а не 299: з цієї IP-адреси в попередньому вікні вже було 73 запити до mastodon.social (браузер, інші застосунки або спільний NAT). Колектор не може вважати, що квота повністю його.
- **`Reset` — це орієнтир, а не гарантія.** На межі 07:20 лічильник не скинувся (`289 → 288 → 287…`), а `Reset` перескочив на 07:30. Тому ми не покладаємось лише на `Reset`: головний сигнал — сам код 429 і `Retry-After`.
- Анонімний `lookup` акаунта теж витрачає квоту (видно на mstdn.social: `299 → 294` після пошуку id).

**2. Закритий анонімний доступ: HTTP 422.** `infosec.exchange` повертає

```
422 {"error":"This method requires an authenticated user"}
```

на стрічку хештегу. Адміністратори частини інстансів вимкнули анонімне читання публічних стрічок (налаштування Mastodon 4.x). Це не тимчасова помилка, тому колектор **не повторює** запит, позначає стрічку помилкою і йде далі. Решта стрічок у тому ж прогоні зібралися повністю. Обхід — токен застосунку зі scope `read:statuses` у `MASTODON_TOKENS`; без токена ця стрічка з дефолтного конфігу прибрана.

**3. Розмір сторінки — максимум 40 статусів.** Тому партія на стрічку обмежена `MAX_PAGES_PER_TARGET=5` (200 постів), backfill — `BACKFILL_PAGES=10` (400).

## Як обходили (без порушення правил)

| Ризик | Захист | Результат |
|---|---|---|
| вичерпати квоту | пауза 1 с між запитами до інстансу; середній темп ~1 запит / 1,4 с | використали 51 з 300 запитів у вікні (17 %), 0 відповідей 429 |
| квота майже вичерпана (інші клієнти з того ж IP) | при `Remaining < 20` запити розтягуються рівномірно до `Reset` | не спрацьовувало: мінімум `Remaining` = 227 |
| 429 | очікування `Retry-After` (секунди або HTTP-дата) → `X-RateLimit-Reset` → backoff; з кількома токенами — перемикання на вільний | перевірено тестами `test_429_respects_retry_after`, `test_token_rotation_on_429` |
| 5xx / обрив | експоненційний backoff 2→4→8… с з jitter, до 5 спроб | `test_5xx_backoff_then_success` |
| закрита стрічка | 401/403/404/410/422 не повторюємо, інші стрічки продовжують | спрацювало наживо на infosec.exchange |

Справжній 429 ми свідомо **не провокували**: у вікні лишалося 249+ запитів, а штучне перевантаження чужого сервера суперечить меті «жодних банів». Поведінку на 429 перевірено на фейковому API з тими самими заголовками.

## Що зберегли

Канонічна таблиця `posts` у `data/posts.sqlite` + експорт `data/export/posts.jsonl` і `posts.csv` (UTF-8 BOM для Excel):

- **обов'язкові:** `author` (`@user@instance`), `url`, `date` (UTC), `text` (HTML → чистий текст, CW як `[CW: …]`), `media` (тип, URL, превʼю, alt-текст);
- **dedup-ключ:** `uid` = ActivityPub URI;
- **службові:** `lang`, `target`, `native_id`, `collected_at`, `run_id`, `extra` (хештеги, лічильники відповідей/бустів/лайків, чи це відповідь);
- окремо: `cursors` (newest/oldest id на стрічку), `runs` (підсумок прогонів), `http_log` (код і заголовки лімітів кожного запиту — з неї й зроблено цей звіт).

Примітка щодо даних: у стрічці `#ukraine` трапляються дзеркала Telegram-каналів через мости ActivityPub (наприклад, `*.anyfeed.cc`). Їхні медіа посилаються на CDN Telegram із тимчасовими токенами, тож такі посилання з часом протухають. Для довгого зберігання медіа треба завантажувати окремо.

Статистика збору — `data/export/dashboard.html`.
